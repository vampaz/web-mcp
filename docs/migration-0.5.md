# Upgrade to 0.5.0

This is a breaking release. No compatibility aliases are included. Install `@vampaz/webmcp-kit@0.5.0` and apply the changes below.

## Node

The package now requires Node 24 or newer (`engines: >=24`) for tooling such as server rendering, tests, and builds. Browser runtime requirements are unchanged. Upgrade projects that install the kit on Node 22 before updating.

## Approval and invocation

| Previous behavior                                                          | 0.5.0 behavior                                                                                                                                                             |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invokeTool({ ..., confirmed: true })` skipped approval                    | The field is removed. Every tool with `confirmation` asks its handler.                                                                                                     |
| Any truthy handler result approved the action                              | Only `true` approves. `'cancel'`, `1`, or a dialog `returnValue` string deny the action.                                                                                   |
| Input only had to support structured cloning                               | Input must be plain JSON. `BigInt`, `Date`, `Map`, class instances, cycles, `NaN` and `Infinity` return `invalid_input`. Object properties set to `undefined` are dropped. |
| Event listeners received the caller's input and the returned result object | Listeners receive copies; changing them cannot change the invocation or the caller's result.                                                                               |
| Output that could not be validated reported `execution_failed`             | It reports `invalid_output`.                                                                                                                                               |

Return `true` explicitly from confirmation handlers:

```ts
setConfirmationHandler(async function approve({ reason, signal }) {
  const choice = await showApprovalDialog({ reason, signal })
  return choice === 'approve'
})
```

Code that already approved an action inside the trusted application boundary should call its own action function directly instead of re-entering `invokeTool()`.

`ToolContext.source` and invocation events now distinguish `'pi'` (previously `'resolver'` for Pi calls) and `'mcp-bridge'` (previously `'fallback'`). The test bridge always uses `'fallback'`.

Two event types are new: `confirmation-requested` and `confirmation-settled`. Their `detail` is `{ id, toolName, source, approved? }`. Update exhaustive `switch` statements over `WebMCPKitEvent['type']`.

## JSON Schema

The validator now enforces `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `uniqueItems`, `minProperties`, `maxProperties`, `propertyNames`, `prefixItems`, `allOf`, `not`, and the `uuid`, `ipv4`, `ipv6`, and `hostname` formats. Schemas generated by Zod for `.positive()`, records, tuples, and intersections are therefore checked instead of silently accepted.

These keywords are rejected when a tool is defined, because the validator cannot enforce them: `$ref`, `$defs`, `definitions`, `$dynamicRef`, `$anchor`, `if`, `then`, `else`, `patternProperties`, `dependentRequired`, `dependentSchemas`, `dependencies`, `contains`, `minContains`, `maxContains`, `unevaluatedProperties`, and `unevaluatedItems`. Inline referenced schemas and express conditional rules in `parseInput()` or `guard()`.

Other `format` values remain annotations. Registration warnings now name them; add a `pattern` or validate in `parseInput()`.

## Resolvers

- The local heuristic resolver no longer scores JSON Schema keywords, requires a minimum match, and fills optional inputs only from evidence in the request. Its built-in invoice status vocabulary is removed; use an `enum` for status fields.
- OpenAI-compatible requests no longer send `temperature: 0` by default. Set `temperature` explicitly when your model supports it.
- Remote, server-endpoint, and hosted failures throw `ResolverError` with `code` (`context_overflow` or `provider_failed`), `status`, and a bounded provider message.
- Resolution validation failures throw `ToolResolutionValidationError`.
- The Chrome resolver updates `status` and `detail` while the model downloads, and a cancelled request stops waiting for the download.

## Pi

- `PiController` has a new required `refresh()` method. Custom controllers passed to chat must implement it.
- Snapshots are deeply frozen and shared between readers. Copy a snapshot before changing it.
- Tool messages carry `input`, `status`, and `output`. Their `text` is the output (success) or error message instead of the raw invocation JSON.
- An action that started before an interruption shows `status: 'unknown'` instead of an aborted failure.
- `clear()` deletes the conversation's IndexedDB database instead of emptying it.
- New limits: `requestTimeoutMs`, `contextTokens`, and `maxMessageChars`.
- `PiError` can include `reason` and `actionMayHaveRun`.
- The resolver message separates historical-reference JSON (`piPreviousConversation`, `piPreviousActions`, and optional `piCheckpoint`) from the current user request. These historical fields are not part of current application context. The model-written checkpoint remains untrusted reference data. Current-turn tool results in `piConversation` are parsed `result` objects without `toolCallId`, `invocationId`, or `durationMs`. Update custom resolvers or fixtures that parsed the previous shape.

New exports: `deletePiConversations()`, `listPiConversations()`, `PiFailure`, and `isPiError`.

## Chat

Rename the controller option:

```ts
chat.configure({ controller, mode: 'popup' })
```

In 0.5.1 and later, “New chat” immediately deletes the current conversation and draft without confirmation. Version 0.5.0 asked for confirmation. Labels, parts, slots, themes, and the imperative API are additive; see [chat](./chat.md).

## Command input

- The Run button becomes Stop during a run and cancels it. Escape cancels a running command before closing the floating panel.
- The visible field label and accessible name default to “Command”. Set `label` or `labels` to localize text.
- `run()` failure results include `code: 'cancelled'` or `code: 'resolver_failed'`.
- An element created by `initWebMCP()` shows a launcher by default. Pass `launcher: false` to hide it.
- The shadow DOM is built once and patched. Style it through `part` names and `--webmcp-*` tokens, not internal selectors.

## Devtools

The overlay renders inside a shadow root. Page CSS that targeted `.wmk-devtools` internals no longer applies. Use `--wmk-devtools-accent` and the `position` option.

## Zod and framework helpers

- `defineZodTool({ examples })` takes raw input (`z.input`), not parsed output.
- Vue, React, and Svelte add `useWebMCPTools(tools, options?)`; core adds `registerTools(tools)`. Both register a set atomically with one disposer.
